# Opper Terraform provider v0.1.0

First release of the Opper Terraform provider, covering declarative configuration through the Management API. This release is being prepared and has not been published to the Terraform Registry.

## Included

Eleven resources manage:

- Projects, default project webhook URLs and project-owned runtime API keys.
- Organization model-list preferences.
- Compliance, guard, observe and routing rules.
- Dynamic-route drafts and conditional live deployments, with separate resources for draft and active configuration.
- Default OpenAI BYOK custom-model definitions, with write-only credentials and explicit credential versions.
- Enterprise custom roles and existing member-role assignments.
- Existing-project Organization or Restricted access policies.

Nine data sources read projects, members, model-list preferences, custom-model metadata, role definitions/catalogs and member-role assignments.

## Install after publication

Use Terraform 1.11 or later as the supported baseline. BYOK write-only credentials require Terraform 1.11 or later. Configure the provider and run `terraform init` after publication:

```hcl
terraform {
  required_version = ">= 1.11"

  required_providers {
    opper = {
      source  = "opper-ai/opper"
      version = "~> 0.1.0"
    }
  }
}

provider "opper" {}
```

Supply a management API key privately through `OPPER_MANAGEMENT_API_KEY`. A runtime API key cannot authenticate to the Management API. The key selects the organization and must grant the scopes required by the resources in the configuration.

## Availability and lifecycle notes

- Required backend APIs are deployed. Project-access policy writes remain disabled by default and require activation for the credential's organization. Publishing this provider does not activate them.
- `opper_project_access` manages existing projects and retains the remote policy on destroy. Creating a project and restricting it afterward does not make it private from creation.
- Custom roles require Enterprise. Member-role assignments manage existing memberships; invitations, membership removal and ownership transfer are not included.
- Runtime-key secrets are returned once and retained in Terraform state. Protect state and saved plans. BYOK credentials are write-only and are not stored in Terraform state.
- Project deletion also revokes all runtime keys belonging to that project, including keys created outside Terraform.
- Terraform controls route drafts and live activation separately. Conditional operations refuse stale plans rather than replacing another writer's changes.

The [live acceptance record](../live-acceptance.md) documents the tested workflows and limits, including completed EKS project-access acceptance. Evroc Terraform project-access acceptance was deliberately omitted; native regional checks are separate evidence. Future API coverage is tracked in the [coverage plan](../coverage.md).
