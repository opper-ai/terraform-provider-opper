# Opper Terraform provider v0.3.0

Brings the provider up to date with the compat model-list features in the
Opper API: the `none` list and the dynamic-routes switch, per-project lists,
and a switch that lets a list also limit which models API keys can call. The
provider now has 12 resources and ten data sources, with Terraform 1.11 or
later required for the full surface.

## Organization model list

`opper_organization_model_list` gains two attributes, and its data source
reports them:

- `compat_model_list` accepts `none`, which lists only the organization's
  dynamic routes. Before this release, an organization set to `none` in the
  platform failed every read, refresh, plan and import of this resource.
- `compat_model_list_dynamic_routes` (optional, computed) sets whether the
  organization's dynamic routes are listed. `none` with the routes off is
  refused at plan time, since it would list nothing.
- `compat_model_list_enforced` (optional, computed) makes the list a limit on
  calls: the organization's API keys, and those of every project that follows
  the organization, can only call the LLM and embedding models the list shows,
  after the rules. Other such models get HTTP 403 with reason
  `model_list_blocked`. Guard checks, observe judges, the models a dynamic
  route calls, and image, video, audio and custom models are not limited.

Both switches are left alone when omitted: the provider never sends them, and
reports the current value. An Opper API that predates
`compat_model_list_enforced` leaves it out of its responses; the provider reads
that as `false`.

## Project model lists

The new `opper_project_model_list` resource gives one project its own list,
which replaces the organization's for compat model-list responses to the
project's API keys. It takes `project_uuid`, `compat_model_list`,
`compat_model_list_dynamic_routes` (default `true`) and
`compat_model_list_enforced`.

- Creation refuses a project that already has its own list. Import it by
  project UUID instead.
- Destroy removes the project's own list, so the project follows the
  organization's list, and its enforcement, again.
- A list removed outside Terraform, or a deleted project, leaves state, and the
  next apply sets the list again.
- While the organization enforces its list, every project is limited, and Opper
  refuses a project list wider than the organization's. The provider explains
  that refusal.

The `opper_project_model_list` data source reports `follows_organization` and,
when the project has its own list, its values. Both need `controls:read`; the
resource also needs `controls:write`.

## Upgrade

The `~> 0.2.0` constraint does not select this release. Change it to require
v0.3.0:

```hcl
terraform {
  required_version = ">= 1.11"

  required_providers {
    opper = {
      source  = "opper-ai/opper"
      version = "~> 0.3.0"
    }
  }
}
```

Run `terraform init -upgrade`, review the provider lock-file change and inspect
`terraform plan`. Existing `opper_organization_model_list` state gains the two
switches on the next refresh, with their current values, and plans no change
when the configuration leaves them out. There is no new management-key scope.
Installing this release does not change any model list, policy or credential.

The organization resource and data source now require the Opper API to return
`compat_model_list_dynamic_routes`, which the hosted Opper API does.

## Verification and limits

Client tests and Terraform CLI tests against loopback API fixtures cover the
new attributes and resource: create, unchanged plans, updates, PUT bodies that
leave unmanaged switches out, import, drift correction, lists cleared outside
Terraform, refusals while the organization enforces its list, uncertain writes,
read and delete failures, destroy, and an API that predates the enforcement
field. The fixtures follow the Opper API source; these features have not had a
live acceptance run against `api.opper.ai`.

See the [organization model-list resource](https://github.com/opper-ai/terraform-provider-opper/blob/v0.3.0/docs/resources/organization_model_list.md),
the [project model-list resource](https://github.com/opper-ai/terraform-provider-opper/blob/v0.3.0/docs/resources/project_model_list.md)
and the [coverage plan](https://github.com/opper-ai/terraform-provider-opper/blob/v0.3.0/docs/coverage.md).
