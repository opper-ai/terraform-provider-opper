# Opper Terraform provider v0.3.1

Fixes creation of project runtime API keys with a nonempty `allowed_ips` list.
The provider now accepts the hosted Management API schema, where updates can
omit `allowed_ips` to preserve the current list. It still checks that both
create and update accept an allowlist before creating a restricted key.

## Upgrade

Run `terraform init -upgrade` with a constraint that permits v0.3.1, such as
`~> 0.3.0`. If you pin an exact version, update the pin first. Review the
provider lock file and run `terraform plan` before applying. The patch
requires no new management-key scopes or Terraform state migration.

If you set an existing key's allowlist outside Terraform, match the configured
list to the live list, remove any temporary `ignore_changes` setting, and
review the plan before applying.

## Verification

Terraform 1.15.3 exercised restricted key creation, an in-place policy update,
preserving the existing list when the field is omitted, and clearing the list
against a local server serving the hosted API's OpenAPI document. A separate
test verified that creation stops before sending a write when the advertised
API lacks allowlist support.
