# Opper Terraform provider v0.2.1

Fixes formatting-only changes when importing existing rules with matching
`jsonencode({...})` configuration. The provider still has 11 resources and nine
data sources, with Terraform 1.11 or later required for the full surface.

## Rule imports

Newly populated desired rule JSON uses compact encoding and sorted object keys.
Matching configuration no longer needs to preserve the API's key order or
whitespace, provided scope, metadata and the complete returned configuration also
match. Array order, string values and numeric precision are preserved, and
`effective_config_json` retains the observed API representation.

Existing desired JSON remains intact while the observed policy is unchanged.
This includes previously imported configurations using `file(...)`. Switching
their configured formatting to `jsonencode` can still need one state-only
update. Number spellings are deliberately preserved: changing an exponent or
trailing-zero representation can still plan an update and send an API PATCH.

Imports recover the full server configuration, including defaults; they cannot
reconstruct the original sparse input. Normalization does not ignore policy
changes or remove defaults. Always inspect the import plan before applying it.

## Upgrade

The existing `~> 0.2.0` constraint permits this patch. A configuration pinned to
`= 0.2.0` must update its constraint explicitly. To require the fix:

```hcl
terraform {
  required_version = ">= 1.11"

  required_providers {
    opper = {
      source  = "opper-ai/opper"
      version = "~> 0.2.1"
    }
  }
}
```

Run `terraform init -upgrade`, review the provider lock-file change and inspect
`terraform plan`. There is no state-schema migration or new management-key scope.
Installing this patch does not change production policies or credentials.

## Verification and limits

The full race suite, vet, CI packaging checks and independent review passed for
the fix. A real Terraform saved-plan test verifies an unchanged rule import with
zero API write attempts, a clean subsequent plan and a later genuine policy
update. Tests also cover precision, escaping, nested objects and array ordering.

Four representative rule configurations in a loopback API fixture reproduced
four import updates with a v0.2.0 source build and zero updates with the candidate.
Saved-plan apply and the follow-up plan passed with zero API writes. Upgrading
legacy imported state preserved both desired and effective JSON byte-for-byte
for all four rules. These are local Terraform/API-fixture results; live Opper API
testing was not repeated for this patch.
